## 职责

### 1. Assay agents、expert specification 与 evaluation（大部分时间）

- 为各数据类型建 agent，顺序：spatial / H&E → ctDNA（与平台工程师合作）→ IHC、cytokine、
  RNA-seq、PK/PD、临床数据。每个 agent：明确输入输出、**每个数字可追溯来源**、有人工审核环节；
  每个 agent 自动化的是同事已在手工做的分析。
- 与 SME 共同写 specification：测量的生物学、数据与 QC、认可的分析流程、**可接受与不可接受的解读**、
  已知失败模式、gold-standard 参考案例、指定审核人。
- 设定上线前的测试用例与 pass criteria；定期 peer review agent 输出。
- 定义并验证 biomarker 的 definition / cutoff / derivation，对科学正确性负责（平台工程师写入 ontology）。
- 输出模板：每个结果附 interpretation + limitations + recommendation，面向项目决策。

### 2. 与转化研究组共同交付（其余时间）

- 牵头 spatial / H&E 首批 pilot，**量化相对现行做法省下的时间**；再按优先级扩展数据类型和研究组。
- 与各组 AI 对接人共建首批工具、审核其科学正确性、教授方法。
- 移交后继续维护 agent 的验证测试并确认仍通过。
- 方法文档化、带 junior 与对接人，提升转化组织整体的计算/AI 成熟度。

### 最好的卖点详解：五种"不靠结果看起来对来判断它对不对"的手段

**一句话**：JD 核心考题 = agent 输出是"被数据支持"还是"仅形式完整"（原文出现两次）。AI agent
天生产出格式对、数字合理、解读通顺的结果 ⇒ 稀缺能力是认出"看起来没问题、实际错了"的那种。
下面五种手段都不依赖"结果看起来对不对"来判断它对不对。

| 手段 | 回答的问题 | 做法 | 我的实例 | 对应 JD 原文 |
| :--- | :---: | :---: | :---: | :---: |
| 独立互证 | 这个数字可信吗 | 同一事实换一条独立路线再算，不一致就至少错一边 | proj37：Adipocyte marker vs Tangram 比例 ρ=−0.01（其余 0.17–0.39），根因是参考仅 15 个细胞 | consistency checks across models、reference results |
| 置换假阳性本底 | 方法本身凭空报多少"显著" | 打乱样本标签跑同一流程，报出的全是假阳性 | proj34：rMATS 18.2% vs LeafCutter 0.1% / DEXSeq 0.2% | benchmark sets、pass criteria |
| 交换样本角色反向跑 | 筛出的 N 个候选是信号还是噪声 | case/control 对调跑同一条过滤链，反向产出 = 本底 | proj31：正向 8 个、反向 9 个 ⇒ 全是噪声 | checks for claims the data do not support |
| 双跑 cmp | 结果是确定的吗 | 同参数跑两遍、产物逐字节比对 | proj37：squidpy p 值是未初始化内存（FDR 虚高 20–40×）；Tangram `seed=0` 没播种（差 0.29） | automated tests、release checks |
| 静默错误清单 | 哪些错不会报错 | 每个零报错的坑写成可执行断言 | Tangram 训练基因 0 个照跑；RCTD 按位置配 ID 错位 29%；DEXSeq 报 0 个显著实为 9301 个 | known failure modes |

- **独立互证**：第二条路线必须独立，同一数据、同一函数重算只会再错一次。对 agent 的意义：agent
  引用的每个数字都可以换一条路线重算核对，正是 JD 的 "traceable source for every number"。
- **置换本底**：不同工具的本底相差两个数量级 ⇒ 必须各测各的，不能借用；它直接决定了 rMATS 当主尺
  还是需要交叉确认。对 agent 的意义：可以作为客观的 pass criterion（置换数据上显著数 ≤ X）。
- **交换反向跑**：置换 = 多次随机打乱，适用于有统计检验的流程；交换 = 一次确定性反向，适用于
  "逐级过滤剩 N 个"、没有 p 值的流程。proj31 的判据滤掉了 99.9% 的噪声，但剩下的仍全是噪声。
  **对照必须逐级对称**：v1 反向少了一级过滤，得到 541 vs 19，看上去像正向干净得多，结论完全反了。
  对 agent 的意义：biomarker cutoff / 候选筛选最需要这种自带的阴性对照。
- **双跑 cmp**：proj37 第一轮 11 步全部 exit=0、断言全过、自审 11 PASS / 0 FAIL；squidpy 用
  `np.empty` 分配的 p 值，一轮读到全零页看似正常，另一轮读到脏页才出现 FDR=−891。对 agent 的意义：
  LLM 本身有非确定性，"同输入跑两遍是否一致"本来就该是 agent release check 的一项。
- **静默错误清单**：每个坑都转成断言（"按名字取交集必须断言 >0"、"内部一致性断言必须配身份对齐
  断言"），写进 skill 和 `software_pitfalls/` 自动执行。对 agent 的意义：spec 里的 known failure
  modes 和 unacceptable interpretations 两个字段，我实际上已经在持续写了。

**为什么是"最好的"**：① 正对 JD 唯一重复出现、并被说成"比面面俱到更重要"的判断力；② 有稀缺性：
多数候选人会说"做过 agent"，少有人能拿出带数字的例子，证明自己抓到过"形式对、内容错"的输出；
③ 能直接对上 JD 的 spec 结构（failure modes、gold-standard、pass criteria、release checks）；
④ 面试时每条都是一个完整故事：所有检查都通过 → 用某手段发现问题 → 定位根因 → 写成永久断言。

**局限（要说实话）**：这五条主要用在**我自己的分析流水线**上，不是专门评估 LLM agent 的输出，
面试时要主动讲出"同一套方法可迁移到 agent 输出"这一步（较接近的现成证据：hook 对 agent 写的报告和
邮件做机械检查）；例子来自内部 pilot（公开数据）或科研客户项目，不是病人来源的临床数据；数字取自
项目记录，没有回原始产物逐个复核。
