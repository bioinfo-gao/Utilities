
多个AI工具，Skill只需装一次
同时用 Claude Code、Codex、Antigravity，skill究竟要装在哪里才合适呢？
装在自己的工作区里，聊着聊着 AI 就发现了，哪怕你在规则里写明了要调用它，还是会漏。而且 Skill 一多，规则跟着变多。
装到工具自己的目录里，倒是能发现了，但三个工具就得装三遍。改了一份，另外两份还是旧的。
🔹 为什么会这样
每个工具只在自己规定的地方找。
• Claude Code 看 ~/.claude/skills 和项目里的 .claude/skills
• Codex 认 ~/.codex/skills
• Antigravity 也是各认各的
你自己新建的目录，它们根本不看。
✅ 我现在的做法
真身只留一份，放在自己的工作区里，跟项目文件待在一起。工具的发现目录里全放软链接指过去。
改的时候只改真身那一份，三个工具同时生效。
📝 建链接不用敲命令，这段话丢给 AI
把我工作区 skills/ 下的每个技能，用软链接挂载到 ~/.claude/skills/、~/.codex/skills/ 和当前工作区的 .claude/skills/ 里。真身不要移动也不要复制，工作区内部的链接用相对路径。建完帮我确认一遍有没有断链。
两处别省：
❌ 不写“不要移动也不要复制”，AI 可能真把文件搬走
❌ 不写“用相对路径”，工作区改个名链接就断
⚠️ 三个坑

1. 工具目录里永远只放链接，不放真身。 工具会重装、会清缓存，真身放那儿会跟着没。
2. 得有一份清单，记每个 Skill 干嘛用的。 我照着清单清过一轮，退役了 7 个。
3. 真身改名或挪位置，所有链接一起断，而且断得没声音，AI 只会跟你说找不到。
   工具一年换好几轮，Skill 是自己的东西，没必要跟着某个工具走。

原文评价

这是一篇非常实用的技术踩坑与最佳实践分享。
• 痛点抓得准：随着 AI Agent 和各类命令行 AI 工具（如 Claude Code 等）的普及，如何管理自定义的“技能/提示词/脚本（Skills）”成为了高频痛点。
• 解决方案优雅：利用操作系统的软链接（Symbolic Link）实现了“一处编写，多处生效”，既保证了代码的单一真身（Single Source of Truth），又迎合了不同 AI 工具固定的读取路径。
• AI 时代的新套路：作者非常聪明地用 Prompt（提示词）代替了复杂的 Linux 脚本命令，让 AI 帮自己去批量创建软链接，降低了操作门槛。
• 避坑指南价值高：最后提到的“工具更新会清缓存导致真身丢失”、“相对路径的重要性”以及“断链无提示”都是实战中极易遇到的血泪教训。

💡 AI 时代的高效 Skill 管理法：一次安装，多端同步

当你同时使用 Claude Code、Codex、Antigravity 等多个 AI 命令行工具时，自定义 Skill（技能脚本/提示词）的存放位置往往让人头疼：
• 放工作区 \(\rightarrow \) AI 经常漏读，且规则文件越写越臃肿。
• 放工具默认目录 \(\rightarrow \) 多个工具要复制多份，同步修改极度麻烦。

🛠️ 核心解法：真身留本地，全局挂软链

让 Skill 脱离具体工具，成为你个人的数字资产。

1. 统一存放：在你的个人工作区（如 ~/workspace/my-skills/）建立一个统一的目录，存放所有 Skill 的“真身”。
2. 软链分发：在各个 AI 工具的默认读取路径下，只存放指向真身的“软链接（Symbolic Link）”。



自动化部署：把这段 Prompt 丢给 AI

不需要自己死记硬背 ln -s 命令，直接把下面这段话发给你的开发 AI：
Prompt：
请帮我把当前工作区 skills/ 目录下的每个技能文件，通过软链接（Symbolic Link）挂载到以下路径：

1. ~/.claude/skills/
2. ~/.codex/skills/
3. 当前工作区的 .claude/skills/
   ⚠️ 严格要求：
   • 禁止移动或复制原文件，必须保留真身在工作区。
   • 链接必须使用相对路径（防止工作区外层目录改名导致失效）。
   • 创建完成后，请自动运行检查，确认没有任何断链（Broken Links）。

🚨 必须警惕的 3 个“隐形坑”

• ❗ 缓存清空风险：各个 AI 工具的配置目录随时可能因为工具升级、重装或清理缓存而被格式化。绝对不要把真身放在工具目录下，否则一键升级，心血全飞。
• ❗ 移动即断链：一旦你修改了本地真身的文件名或移动了文件夹，外部所有的软链接会瞬间全部失效。最糟糕的是，这种失效是“无声”的——工具不会报错，AI 只会装作找不到。
• ❗ 缺乏资产清单：Skill 积累多了容易变成垃圾场。建议在真身目录下维护一个 README.md，记录每个 Skill 的核心功能。定期盘点，及时让老旧 Skill “退役”。
💡 总结：流水 contract 的 AI 工具，铁打的个人 Skill。把核心资产牢牢握在自己手里，才能做到“工具一年换三轮，我自岿然不动”。
