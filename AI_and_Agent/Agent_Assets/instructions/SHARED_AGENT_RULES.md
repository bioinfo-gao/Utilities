  ### §2A 科学分析严谨性：先审证据模型，再写脚本或开跑 (MANDATORY — user directive 2026-10-22)
  - **每一项科学分析在正式运行前，必须把“研究问题 → 观察/证据单位 → 保留与去重规则 → 判定指标 → 允许的结论”写成可审查的 decision table。** 只列工具、参数和阈值不算完成：必须说明每条过滤规则为什么服务于研究问题，以及删掉它会遗漏哪类证据。
  - **严禁把“不是独立分子”误处理成“没有分析价值”。** 对 read/alignment 数据，independent-molecule count 与 mapping evidence 是两个层次：可按 read/fragment identity 去重计数，但不得仅为避免双计数而删除原始 alignment context。所有被合并的 record 必须仍可追溯到原 FLAG、坐标、CIGAR、MAPQ 和过滤原因。
  - **当研究问题涉及 repeats、multi-mapping、SV/junction、融合、整合位点、同源区域或“真实位置/来源判定”时，primary、secondary、supplementary alignment 必须分开记录和解释。** secondary 不是额外独立分子，却可能是定位歧义的直接证据；supplementary 不是额外独立分子，却可能是 split/chimeric structure 的直接证据。不得把 primary label、单一 MAPQ 阈值或单一 best hit 写成真实 locus 的充分证明。
  - **先定义 data universe，再定义 candidate universe。** 若分析目标是某空间窗口、某类原始观测或 discovery，不能先用旧 caller / 旧 candidate table / 旧 read-name 列表封闭输入，再把未入选数据默认写成无关。旧结果可作为 comparison annotation；若要作为唯一输入，必须在计划中论证它不会排除研究问题所关心的 evidence，并经用户确认。
  - **每个过滤条件都必须有 filter-impact audit。** 正式输出至少给出过滤前后 record、read-name/fragment、candidate 的数目和可追踪的原因；关键过滤应保留 machine-readable excluded/audit table。没有输出“被过滤的是什么、过滤了多少”，不得声称某类证据不存在。
  - **`SEQ` 可用性与 sequence 完整性必须分开审计。** `SEQ` 非空只证明有可重比对输入；不能自动证明保存了完整原始 read。对需要 base-pair-level 解释的分析，必须检查 hard/soft clipping、sequence length、read-end identity，必要时回溯原始 FASTQ 或完整记录。
  - **重比对、重调用或再次运行同一数据，不是独立生物学验证。** 报告必须说明它验证的是 algorithmic/mapping reproducibility、multi-fragment support、还是独立样本/assay；不得跨越证据层级下结论。
  - **若在运行中或审阅中发现 evidence model 与研究问题不匹配，立刻停止将现有产物表述为完整答案。** 保留代码、参数、日志、结果和问题审计；不删除、不原地覆盖。重新设计后以新目录/新日期运行，并将旧版本归档为可比较的历史记录。
  - **对会改变 data universe、evidence unit、去重口径、候选定义或结论层级的选择，必须在正式运行前向用户说明并取得确认。** “自动/全流程”授权执行已经明确的方案，不授权在上述科学口径存在实质歧义时自行选择。

  **任何时候我把一件事交给人去看、去判断、去核验、去过目、去决定**，都适用。

  1. **精确路径**（写明绝对路径还是相对于哪个根）。禁止只说"面板""那些图""报告""输出目录里"。
     本 harness 里写成**可点击的 markdown 链接**。
  2. **数量**。"12 张"而不是"若干张" —— 数量是用户自查有没有看漏、我有没有偷工的唯一凭据。
  3. **看什么**（判据）：要判断的具体问题、什么样算通过、什么样算否。
  4. **看完做什么**：结论写到哪个文件、以什么形式反馈。"看完就算"不是交代。

  - **多文件给 glob + 数量**，或给一条能直接列出全部文件的命令。
  - **文件需要转换才能看**（PDF→PNG 等）→ **直接给出可复制粘贴就能跑的命令**，
    并说明转换产物落在哪（scratchpad）、看完即删、交付只留原格式。
  - **同名文件存在多个版本时必须显式警告并说清哪个是当前有效版** ——
    「修正前必须归档旧版」那条规则**必然**制造同名多版本，所以这是它的配套义务。
    （proj29 实测：同一批判读图三处同名，打开缺陷版看到"零证据"、有效版看到"20 条成簇读段"，
    **结论完全相反**，而用户不会知道自己看错了。）

## 无 path 指代 = 当前打开的文档 (MANDATORY — 已重复 4 次，4 级机械化)

  - 请求里出现无 path 指代 —— `本文`/`本节`/`这个文档`/`该文件`/**`这个位置`**/`这一处`/
    `这里`/`这段`/`这句`/`它` —— **一律解析为当前打开的文档**（最近一条 `<ide_opened_file>`）。
    指"位置"的那几个词 = **该文档内部的某处**。不是待考证的歧义，不是去搜这句话出自哪里。
  - **强制输出约束**：这类请求的回复**第一句必须写出解析到的绝对路径**
    （「本文 = `/abs/path/x.md`（当前打开）」），然后**直接动手**。
  - **⛔ 不许全局搜索，也不许用 AskUserQuestion 去问是哪一份。**
    **「我觉得这样解析不合逻辑」永远不构成例外** —— 堵住"搜"我就会改用"问"，两者是同一件事：
    不肯按默认解析动手。按默认动手若真错了，用户一句话纠正的成本远低于多一个来回。
  - **⛔ 唯一的前置校验**：用户在消息里**引用了一段原文**时，**动笔之前**先
    `grep -F "<那段原文>" <解析到的文件>` —— **0 命中 = 解析被证伪，此时必须问 path**，禁令不适用。
    **写进去之后再 grep 是我自造的证据，不算数。**
  - 唯一允许提问的另一种情形：本轮上下文里根本没有 `<ide_opened_file>`，
    **且已先跑过一次 workspaceFolders 兜底搜索**（2026-09-11 收窄）。
    **「没有 `<ide_opened_file>`」≠「用户没开文档」** —— CLI 只在 IDE 推来 selection 状态时
    才发那条提醒，文档早开着、用户没点进正文就永远不会发。此时 `~/.claude/ide/*.lock` 的
    `workspaceFolders` 就是可信搜索根，hook 会连同一条现成的 `grep -RF` 命令一起注入，照跑即可。
  - **确实需要查找时，顺序固定，不得跳级**（user directive 2026-07-21）：
    **① 当前工作文档**（本轮刚读过/刚写过/正在编辑的那份）→ **② IDE 里打开的其它文档**
    → **③ 其余一切情况：用户一定会主动给路径**。
    **除前两处之外，不存在"我该去全局搜索"这个选项** —— 找不到就如实说"当前文档与编辑区打开的
    文档里没有这个内容"，请用户给路径。跨项目 `grep`/`find` 几乎总是在浪费工作量。
  - **⇒ 已机械化**：`hooks/resolve_current_doc.py`（UserPromptSubmit）检出指代词就把解析好的
    绝对路径注入上下文，我不需要记得。

  - **与下一节分工**：「做什么/多大范围/什么口径」有疑问 → 开跑前问；

## Autonomous execution — 自动跑到底，除非硬阻塞 (MANDATORY — user directive 2026-07-16)

### 活跃项目连续性不变量（MANDATORY — user directive 2026-10-23）

  - 用户授权“自动／全流程／全过程”后，项目在完成定义达成前必须登记为 **active**；登记的 SSOT 是
    `Agent_Assets/runtime/active_projects.json`。每项 active 记录必须有项目绝对路径、当前阶段、下一可运行阶段、
    期望 tmux session、状态（`running` / `blocked` / `complete`）和最后验证时间。
  - **每项 active 记录必须写 `agent`（`codex` / `claude_code`），并在本 Agent 的
    `runtime/<agent>_active_project_autostart.json` 登记会话**（user directive 2026-10-25：不同 Agent 的项目不互相混淆）。
    改写 SSOT 时保留已有字段。额度用完后的自动续跑：优先在提示给出的重置时间 +5 min 重试，兜底 3/4/5 h 各一次；
    仍失败则由控制器标 `blocked` 并发邮件，不无限重试。
  - **任何 stage 正常结束不等于项目结束。** 在当前 turn 结束前，Agent 必须完成且验证以下三者之一：
    1) 已在 tmux 启动下一可运行 stage；2) 已将项目标为 `complete`，并且交付定义已经满足；3) 已标为
    `blocked`，明确写出不可由 Agent 解决的阻塞、影响和需要用户作出的唯一决定。没有活跃进程、没有后续
    tmux、又没有 `complete/blocked` 的项目状态，属于执行失败，**不得以“阶段完成”或“等待用户”结束。**
  - 每次向用户报告“项目进展”时，必须先实测并写明：运行中的程序、tmux session、已完成 stage、下一 stage；
    如果没有运行程序，必须把它表述为异常状态并在同一 turn 恢复下一 stage，而不得把资源空闲包装成进展。
  - Client Stop hook 是 defense-in-depth：active 项目若目标 tmux 不存在，**支持该事件且已实际 trust/enabled 的客户端**必须继续该 turn，要求启动下一 stage 或更新为有证据的 `complete/blocked`。Agent 专属 adapter 可以不同，但判断状态只能读取上述中心 SSOT；不得创建另一份“活跃项目”清单。
  - **不得把某个客户端的 hook 列表或配置文件存在，误报为该客户端已经执行 lifecycle hook。** 若客户端缺少可用的 trust/review 或 Stop-hook 支持，必须明确标为未覆盖。
  - 跨 Agent 的最低强制层是本机 cron 的 `continuity_guard.py`：它独立读取同一 SSOT，每 **10 分钟**检查 `active` 项目的预期 tmux。`active` 但预期 tmux 缺失定义为**严重事件**：首次发现及持续 30 分钟未恢复时，必须同时写本地审计日志、广播 tty，并使用独立 SMTP notifier 发送邮件；正常、`blocked`、`complete` 状态绝不发信。它只报告、不擅自启动/杀死/改变分析；处理异常后仍须由 Agent 将状态更新为 running、blocked 或 complete。

## 长任务必须在 tmux 里跑 (MANDATORY)

  - 这是远程服务器。**任何预计超过几分钟的命令**（管线、nextflow、长比对、大下载、训练）
    **必须放进 `tmux`**，不能用 Bash 工具自带的后台模式 —— 后者绑在 agent 会话上，
    断连/重启就被杀；tmux 把任务寿命和会话解耦。
  - `tmux new-session -d -s <name> 'cd /path && command 2>&1 | tee log.txt'`；
    事后用 `tmux capture-pane -t <name> -p` 或直接 tail 日志，不要交互式 attach。
  - 已经跑在 tmux 外的长任务，**尽快 kill 后用 `-resume` 重新放进 tmux**，别让它裸奔。
  - 启动后的早失败检测与状态检查见 `watchdog` skill。

## CPU / 线程硬上限 (MANDATORY — 所有同时运行的线程加总)

  - **持续上限：28 物理核 / 56 线程** —— 长于几分钟的分配一律按这个天花板设计。
  - **短时突发（仅忙时）：最多 30 核 / 60 线程**，只用于吸收任务重叠的瞬时峰值，
    **不得持续**；30/60 是绝不逾越的硬顶。**永远留 ≥2 核 / 4 线程**给 OS、SSH 和交互。
  - **单个长任务按 28/56 设计，不要按 30/60。**
  - 管道内各进程并行，**线程数相加**（如 fastp -w 8 + bwa -t 40 + samtools sort -@ 8 = 56）。

## Single source of truth — 同一份信息不存两次 (MANDATORY)

  - 一个项目/文件夹内不要保留同一份数据的两个副本（如 sample sheet 同时有 `.md` 和 `.tsv`）。
    像数据库一样，重复的信息在其中一份被改、另一份没改的那一刻就静默不一致了。
  - 保留**一个** canonical 文件，优先机器可读格式。
  - 叙述性文档若必须展示这些数据，要么引用 canonical 文件，要么把内嵌副本当作
    **在同一次回复里同步更新**的忠实镜像 —— 绝不允许两者漂移。
