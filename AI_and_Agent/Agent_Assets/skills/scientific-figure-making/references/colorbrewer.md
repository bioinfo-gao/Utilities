# 配色遇到困难 → 先去 ColorBrewer 查，不要自己发明调色板

> user directive 2026-08-05：「颜色选择有困难到这里寻找配色方案，这句应该成为 skill 的一部分。」

**入口：https://r-graph-gallery.com/38-rcolorbrewers-palettes.html**

ColorBrewer 的色板是**按感知做过工程验证**的，而且天然按角色分好了组 —— 正好对上
「文字要深、色块要软」那条原则（见 [house-style.md](house-style.md) §4a-2）。
自己手调一组颜色要反复算距离、试饱和度；从这里取一组，起点就已经是对的。

---

## 按角色取色

| 角色 | 取哪种色板 | 为什么 |
| :--- | :--- | :--- |
| **色块**（bar / rect / area / box / 地图多边形） | **qualitative**：`Set3`（12 色）、`Pastel1`、`Pastel2`、`Set2` | 天生低饱和，大面积铺开不刺眼、不盖过数据 |
| **线条 / 文字** | **先用 `STROKE_COLORS` 六色**（见下），用完再取 **diverging 两端深色**：`PRGn`、`PiYG`、`BrBG`、`RdBu` | 深且饱和，一两像素宽的笔画才立得住 |
| **点 / 小 marker / 强调** | **qualitative 饱和款**：`Dark2`、`Set1` | 小面积需要饱和度才看得见 |
| **连续量**（表达量、深度、密度） | sequential：`Blues`、`YlGnBu`、`viridis` | 单调有序，可读出大小 |

**`Set3` 是主力**：12 个彼此可分的低饱和色，多分组的柱状图/堆叠图一次够用。

`brewer()` 在 Python 与 R 下同名同结果：

```python
from pubfig import brewer, BREWER_ROLES
fills = brewer("Set3", skip=[1, 11])   # 跳过两个黄色成员
j2, j1 = brewer("PiYG", 2)             # n=2 精确给出两端深色
```
```r
fills <- brewer("Set3", skip = c(2, 12))   # R 是 1-based
ends  <- brewer("PiYG", 2)
```

## 三条必须知道的坑

**① 名气不等于安全 —— 取回来照样要过断言。**
`Set3[1] = #FFFFB3` 对白底 WCAG 对比度只有 **1.04**，连填充阈值 1.1 都不到，
正是「浅黄陷阱」，就藏在这个公认优秀的色板里。`Set3[11] = #FFED6F` 也是黄色（1.19）。
**任何做文字的场合这两个都不能用。**

**② 同一色板内部也可能撞车 —— 跨面板取切片仍必须过 `assert_no_palette_collision`。**
Set3 的 12 色作为整体是可分的，但 `#80B1D3`(蓝) 与 `#8DD3C7`(青绿) 在本 skill 的距离
度量下只有 **0.096**，低于 0.10 阈值。上下面板各取一段时，这两个不能分处两端。

**③ 距离阈值只是防意外撞车的粗筛，不要拿它去否定 ColorBrewer。**
本 skill 的 `_rgb_distance` 是个简易代理指标；ColorBrewer 是做过感知验证的。
低饱和色板成员之间距离普遍偏小（Set3 内部常见 0.12–0.15），**这在实际观感上是够分的**。
阈值存在的意义是拦住"两个随手挑的颜色恰好撞了"，不是替你判定 Set3 不合格。

## 线条与文字：先用这六个久经考验的颜色

> user directive 2026-08-05：「线条和文字标注，优先使用黑色，正红，亮蓝，深绿，咖啡，深紫色
> 这几个颜色。这几个是久经考验的视觉醒目的颜色。然后是 PRGn PiYG BrBG 等两端极化的深色调。
> 这些加在一起就足够用了。」

`STROKE_COLORS` —— **按优先级取用，从上往下**：

| 序 | 名称 | 色值 | 对白底对比度 |
| :---: | :--- | :---: | :---: |
| 1 | 黑 | `#000000` | 21.00 |
| 2 | 正红 | `#E41A1C` | 4.71 |
| 3 | 亮蓝 | `#1F78B4` | 4.77 |
| 4 | 深绿 | `#006D2C` | 6.51 |
| 5 | 咖啡 | `#8C510A` | 6.37 |
| 6 | 深紫 | `#762A83` | 8.64 |

**六色两两最小距离 0.221 —— 比任何填充色板都分得开**（Set3 内部常见 0.12–0.15）。
色相分布在 359° / 204° / 144° / 33° / 291° 加黑色，彼此不可能混淆。

**黑色排第一**：永不出错、不占色相位，也是颜色不够用时的兜底。

**第二梯队**：`brewer("PRGn", 2)` / `("PiYG", 2)` / `("BrBG", 2)` 的两端极化深色。
注意它与第一梯队**略有重叠**（`#00441B` 距深绿 `#006D2C` 仅 0.087），
所以动用第二梯队前先看看第一梯队已经用掉了哪几个。

⚠ **前提是白底或浅底** —— 这覆盖绝大多数图，本 skill 所有检查
（`contrast_vs_white`、`assert_visible_on_white`）都是按这个前提写的。
少数深色背景下逻辑镜像反转：**白色与浅色单色线条**接管，上面这六个反而看不清。
本 skill 不提供深底检查器；真要做，应把亮度判据反过来，而不是复用这组色值。

## 推荐用 `set3_with_grey()` 而不是原版 Set3

> user directive 2026-08-05：「我建议 Set3 内部的 #80B1D3 用一个深一点的灰色取代，
> 灰色还是重要的，不然多一个可用配色还是很重要的。」

**把 Set3 的蓝 `#80B1D3` 换成中灰 `#999999`** —— 一次替换同时解决两件事：

1. `#80B1D3`(蓝) 与 `#8DD3C7`(青绿) 距离仅 **0.096**，低于阈值，二者**永远无法分处两个面板**，
   等于白白损失一个可用色。换掉蓝之后 `#8DD3C7` 就解放了（本项目实测候选池 7 → 8）。
2. Set3 唯一的中性色 `#D9D9D9` **太浅**（对比度 1.41）。**一个能用的中灰比第二个冷色更值钱** ——
   灰色承担「参照 / 背景 / 其它」这类语义，不占用色相位。

`#999999` 对比度 2.85，落在 Set3 自身 1.29–3.02 区间内，读起来像同族成员而非闯入者；
与 Set3 自带的 `#D9D9D9` 相距 0.251，两个灰并存无碍。

⚠ **必须换成更深的灰，不能更浅**：`#BFBFBF` 距 Set3 的淡紫 `#BEBADA` 只有 **0.063**。

```python
from pubfig import set3_with_grey
fills = set3_with_grey()      # 索引与原版 Set3 一一对应，便于对照
```
```r
fills <- set3_with_grey()
```

## 颜色不够用时的兜底

1. **文字标注一律改黑色** —— 永远不会错，也不消耗色相空间。
   （用户原话：「当颜色不够用时，文字标注用黑色又是不会出错的兜底保险」。）
2. **分割线可以直接用红/绿/蓝** —— 分割线不承载分组语义，用最基本的三原色即可，
   不必从分组色板里挪一个出来。
3. 还不够，再考虑**第二通道**：hatch / linetype / shape，而不是硬挤第 13 个颜色。
