# awk —— pattern 与 `{action}` 之间换行 = 过滤条件彻底失效，且零报错

**症状**：一条 awk 过滤命令看起来完全正确，但输出的是**整个输入**，过滤条件像不存在一样。
没有语法错误、没有警告、退出码 0。

**踩坑写法**（P29，2026-08-13 实测）：

```awk
$4>=q && $2 ~ /^chr/ && ($1=="ori" || $1=="KanR" ||
                         $1=="M13_lac_CAP")
{print $1,$2,$3,$4,$5}
```

**根因**：awk 的程序是 `pattern { action }` 的序列，而**换行是规则的分隔符**。
上面这段被解析成**两条独立规则**：

1. `$4>=q && ... )` —— 一条只有 pattern 没有 action 的规则 ⇒ 执行**默认动作 `print $0`**
2. `{print $1,...,$5}` —— 一条只有 action 没有 pattern 的规则 ⇒ **对每一行都执行**

于是每一行都被打印，还正好是 5 列，格式看着完全正常。
P29 因此把"骨架↔基因组接头读段 1104/1187/2072/7294 条"写进了判定，
**实际那只是该 contig 上的全部读段**（真值 37/49/41/184，差 20–30 倍），
并据此给出了"整条质粒整合"的结论。

**规矩**：
1. **`{` 必须与 pattern 在同一行。** 条件太长要换行，就让上一行以 `&&` / `||` 结尾
   （运算符结尾才是行内续行），或者干脆把 `{` 提到那一行末尾。
2. 多值判断改用 **BEGIN 里建关联数组**，条件短到一行写得下，可读性也更好：
   ```awk
   BEGIN { split("ori KanR M13_lac_CAP", a, " "); for (i in a) bb[a[i]] = 1 }
   ($1 in bb) && ($2 ~ /^chr/) && ($4 >= q) { print $1, $2, $3, $4, $5 }
   ```
3. **写完加一条硬断言回头验证"这个文件里装的真的是我要的东西"**（列取值范围、行数量级）。
   这次 bug 能一路走到结论，正是因为没有任何一条检查回头看过输出内容 ——
   见 [[feedback_self_audit_needs_independent_cross_check]]。

**顺带一条同源的坑**：`if (seg !~ $1)` 是把 `$1` 当**正则**匹配，不是集合判等。
要去重就用 `segset[$1]=1` 配 `for (k in segset)`，别用字符串拼接 + `!~` 近似。

**mawk vs gawk**：本机默认是 mawk（`awk --version` 会报 "not an option"，
`awk -W version` 才行）。`delete arr` 整表删除 mawk 支持；`length(arr)`、`asort()`
等 gawk 扩展**不要用**，脚本会在别的机器上换 awk 实现时静默行为不同。
