## §0 TL;DR —— 如果你只读一节

### 0.1 直接结论：R 还是 Python？

**答案：R 做下游统计与出图（主语言），Python 做原始数据处理与工具粘合（工具箱）。搜索引擎层根本不是"R 还是 Python"的选择题。**

这个格局**和你的 scRNA 选型正好相反**。scRNA 那边是 Python 主线（Scanpy）+ R 补三块；蛋白质组学这边是 **R 主线 + Python 补三块**。原因不是历史惯性，而是一个硬事实：

> **蛋白质组学差异分析所依赖的统计方法（limma 的经验贝叶斯方差收缩、MSstats 的线性混合模型、msqrob2 的稳健回归 + 缺失值建模），在 Python 里没有等价实现。**
> 不是"Python 版本差一点"，而是**不存在**。而这些方法恰恰是小样本（n=3）蛋白组项目能不能得出可辩护结论的关键。

分层结论表：

| 分析层 | 赢家 | 差距大小 | 说明 |
| :--- | :---: | :---: | :---: |
| 原始文件 → 鉴定 + 定量（search） | **语言无关** | — | DIA-NN / FragPipe / MaxQuant 是独立二进制或 GUI，你只是调用者 |
| 重打分（rescoring）、深度学习预测谱图 | **Python** | 大 | mokapot / Oktoberfest / AlphaPeptDeep 全在 Python，R 无等价物 |
| 原始文件解析（mzML / .d / mzIdentML） | **Python** | 中 | pyteomics / pyOpenMS 成熟；R 侧 mzR 可用但生态薄 |
| 定量矩阵组装与 QC | **R 略胜** | 小 | QFeatures 提供统一数据契约；Python 侧 alphastats 可用但抽象层弱 |
| **差异丰度统计** | **R 压倒性** | **极大** | **Python 没有 limma / MSstats / msqrob2 / proDA / DEqMS 的等价物** |
| 富集分析与通路解读 | **R** | 大 | clusterProfiler / fgsea / ReactomePA 生态完整（你已经在用） |
| 出版级图件 | **R** | 中 | ggplot2 + 你已有的 house style；且与 RNAseq 报告统一 |
| 单细胞蛋白质组学 | **R 略胜** | 小 | Bioconductor `scp` 是该领域参考实现；但规模上去后 Python 更顺 |
| 管线编排 | **Nextflow** | — | nf-core/quantms，与你已熟的 sarek / rnaseq 同一套心智模型 |

### 0.2 给你的具体技术栈（三选一，按项目类型）

| 项目类型 | 搜索层 | 统计层 | 备注 |
| :--- | :---: | :---: | :---: |
| **DIA（数据非依赖采集）—— 首选默认** | **DIA-NN** | R：`limma` 或 `msqrob2` | 2026 年的默认路线；单次进样深度最好 |
| **TMT / TMTpro（同位素标记多重）** | **FragPipe**（TMT-Integrator） | R：**`MSstatsTMT`** | plex 就是批次，必须用能建模批次的方法 |
| **LFQ-DDA（无标记数据依赖采集）** | **FragPipe** 或 **MaxQuant** | R：`limma` + `DEqMS` | 老项目 / 客户已有 MaxQuant 结果时 |

**Python 在这三条路线里的固定位置**：解析原始文件（`pyteomics`）、批量重命名与 SDRF 样本表生成、把搜索引擎输出规整成矩阵、以及未来做 rescoring 或 de novo 时。**不做统计。**

### 0.3 五个必须先卸载的 RNAseq 直觉

| 你的 RNAseq 直觉 | 在蛋白组学里 | 后果 |
| :--- | :---: | :---: |
| 定量单位是**计数（count）**，所以用负二项分布（DESeq2 / edgeR） | 定量单位是**强度（intensity）**，连续量，近似对数正态 | **绝不能用 DESeq2。** 用了会得到无意义的 p 值 |
| 缺失值很少，`0` 就是"没表达" | 缺失值占 **20–50%**，且 `0` 通常意味着**"低于检出限"而不是"不存在"** | 当成 0 参与计算 = 系统性偏倚 |
| 每个基因都会被测到（覆盖是均匀的） | 检测是**丰度依赖的半随机采样**，低丰度蛋白系统性漏检 | 富集分析的背景集不能用全基因组 |
| 一条 read 归属一个基因（multi-mapping 是少数派） | 一条肽段**经常同时属于多个蛋白**（蛋白推断问题） | protein group 与基因符号是**多对多** |
| n=3 够用 | 同样的 n=3，**检出力更低**（技术变异更大 + 缺失值） | 阴性结论必须写明检出力限制 |

## §1 先卸载：质谱不是测序

这一节是全文最重要的部分。**迁移过来的人 90% 的错误都源自把质谱当成"蛋白质版的 RNA-seq"。**

### 1.1 根本差异：没有扩增，就没有均匀覆盖

DNA/RNA 测序的一切统计学，建立在一个隐含前提上：**核酸可以被扩增**。PCR 让一条起始分子变成百万条，于是低丰度和高丰度的分子最终都能进入测序仪，差别只是 read 数多少 —— 这就是为什么 count 模型（负二项）成立，也是为什么"测得越深，检出越全"。

**蛋白质不能被扩增。** 质谱仪测的是**当场存在的分子**。这带来三个连锁后果：

1. **动态范围是硬约束，不是深度问题。** 细胞裂解液里蛋白丰度跨越约 **7 个数量级**，血浆跨越 **10–12 个数量级**【文献】。而单次质谱分析的实际可及动态范围约 **4–5 个数量级**【量级估算】。**⇒ 最低丰度的那部分蛋白，无论你测多久都测不到**，除非先做富集或去除高丰度蛋白（depletion）。这与"RNAseq 测深一点就能看到低表达基因"完全不同。
2. **"测序深度"这个变量被"梯度长度 + 仪器扫描速度"取代。** 你能调的是液相色谱（LC，liquid chromatography）梯度时间（例如 30 min vs 120 min）、进样量、以及是否分级（fractionation）。**加时间的边际收益衰减极快**，远不如 RNAseq 加深度线性。
3. **同一批样本的检出蛋白清单，每次跑都不完全一样**（尤其 DDA 模式）。这是**采集策略**造成的，不是技术故障 —— 见 §1.3。

### 1.2 分析对象不是"蛋白质"，而是"肽段"

**质谱几乎从不直接测完整蛋白。** 标准流程（自下而上，bottom-up / shotgun proteomics）是：

```
蛋白质混合物
  → 用胰蛋白酶（trypsin）酶切成肽段（peptide）      ← 信息在这一步被打碎
  → 液相色谱分离
  → 质谱一级扫描（MS1）测肽段质荷比
  → 碎裂肽段，二级扫描（MS2）测碎片
  → 用碎片谱图比对蛋白质序列数据库，鉴定肽段
  → 把肽段"拼回"蛋白质                              ← 信息在这一步被不完全地重建
```

**这个"打碎再拼回"是所有蛋白组学特殊性的根源。** 类比：想象你把 RNAseq 的 read 长度砍到 8–25 bp，然后禁止使用基因组坐标，只能靠序列匹配来决定这条 read 属于哪个基因。你立刻会遇到：

- **多归属（protein inference problem）**：一条肽段的序列可能同时存在于 3 个同源蛋白里。软件的处理是把它们打包成一个 **protein group（蛋白组）**，输出里写成 `P12345;Q67890;A0A123`。**这不是错误，是诚实。** 下游做基因富集时你必须决定取哪一个（惯例：取第一个 = leading/razor protein），而这个决定会静默影响结论。
- **蛋白异构体（isoform）基本不可分辨**：同一基因的不同剪接异构体往往共享绝大部分肽段。**⇒ 你在 RNAseq 里做的 isoform 级分析，在标准 bottom-up 蛋白组里做不了**，除非该异构体恰好有独有肽段（unique peptide）覆盖。这一点在跟做剪接的合作者对话时经常被误解。
- **覆盖度极不均匀**：一个 100 kDa 的蛋白可能只有 5 条肽段被测到，序列覆盖度 8%。**⇒ 结构域级别的结论（"N 端片段增加"）需要专门设计，不能从常规数据里读出来。**

> **【判断】** 如果客户问"能不能看某个蛋白的某个特定异构体/片段"，默认答案是**不能，除非专门做靶向方法（PRM/MRM，见 §2.3）**。这是我认为最容易在项目启动阶段给出错误承诺的地方。

**自上而下（top-down proteomics）** 直接测完整蛋白、能分辨 proteoform，但通量低、技术门槛高、生态小众。**【判断】** 除非客户明确要求且付得起，不进入常规服务菜单。

### 1.3 缺失值：这是蛋白组学与 RNAseq 最大的操作性差异

一个典型的无标记（label-free）蛋白组定量矩阵，**20%–50% 的格子是空的**【量级估算】。而且这些空格**不是随机的**：

| 缺失机制 | 英文全称 | 成因 | 正确处理 |
| :--- | :---: | :---: | :---: |
| **MNAR** | missing not at random（非随机缺失） | 蛋白丰度**低于检出限**。它确实存在，只是没被测到 | **不能当 0，也不能用均值填补。** 应该用"左删失（left-censored）"模型，或填一个"很低的值" |
| **MCAR** | missing completely at random（完全随机缺失） | DDA 采集的随机性、色谱漂移、鉴定失败 | 可以用邻近样本信息填补（kNN 等） |

**为什么这件事致命**：假设蛋白 X 在处理组 3 个样本里都测到（强度 1e6），在对照组 3 个样本里都没测到。

- 如果你**填 0** → log2 变换后是 `-Inf` 或人为设的极小值 → t 检验给出天文数字的显著性 → **假阳性**；
- 如果你**直接丢弃含缺失的行** → 这个蛋白被删掉 → **而它恰恰可能是最有生物学意义的那个（完全的 on/off 变化）** → 假阴性；
- 如果你**用行均值填补** → 处理组和对照组被拉平 → 假阴性。

**⇒ 三种"想当然"的做法全是错的。** 正确路线见 §7.3。这也是为什么蛋白组学必须用专门的统计包，而不能把矩阵丢进 limma 就完事。

### 1.4 定量数值的性质：强度，不是计数

搜索引擎输出的"定量"是**色谱峰面积或谱图强度**，是连续的正实数，跨越几个数量级。

- **分布**：log 变换后近似正态 ⇒ **对数正态（log-normal）**，不是泊松/负二项。
- **⇒ DESeq2、edgeR 在这里无效**，因为它们的方差-均值关系假设（负二项）不成立。用了不会报错，只会给你无意义的结果 —— **这是最隐蔽的错误类型，因为输出长得完全正常。**
- **正确工具**：`limma`（对 log 强度做线性模型 + 经验贝叶斯方差收缩）、`MSstats`（线性混合模型，直接建模到 feature 层）、`msqrob2`（稳健回归 + 显式缺失值处理）。

> **⚠ 唯一的例外**：**谱图计数（spectral counting）**是真正的计数型定量（数某个蛋白被多少张谱图支持）。它可以用计数模型。但它精度差、动态范围窄，**在 2026 年已基本被淘汰**，只在极老的数据里遇到。【判断】不要因为"这样就能用 DESeq2 了"而退回去用它。

### 1.5 蛋白丰度 ≠ mRNA 丰度

**mRNA 与蛋白丰度的跨基因相关系数（Spearman）通常在 0.4–0.6 之间**【文献，Liu / Beyer / Aebersold 等多项研究一致】。

这不是技术噪声，是生物学：翻译效率、蛋白半衰期、降解调控各自独立。**⇒**

- **不要用 RNAseq 结果去"验证"蛋白组结果，反之亦然。** 两者不一致是常态，不是任何一方出错的证据。
- 在报告里写多组学整合时，**必须先声明这个基线相关性**，否则客户会把 0.45 的相关性读成"分析失败"。
- 反过来，**一致的那部分子集**恰恰是最有说服力的发现（转录与翻译层同向变化）。这是整合分析真正的价值所在，见 §9。

## §2 数据类型分类学：先搞清你的项目属于哪一格

**在动任何分析之前，必须先确定三个正交的维度。** 这三个维度的组合决定了后面每一步用什么工具 —— 搞错了会整条重跑。

### 2.1 维度一：定量策略（标记 vs 无标记）

| 策略 | 英文全称 | 原理 | 多重度 | 优势 | 代价 |
| :--- | :---: | :---: | :---: | :---: | :---: |
| **LFQ** | label-free quantification（无标记定量） | 每个样本单独进样，比较色谱峰面积 | 1 | 便宜、样本数无上限、动态范围好 | 批次效应大、缺失值多、机时 = 样本数 |
| **TMT / TMTpro** | tandem mass tag（串联质量标签） | 化学标记后**多样本混合成一管**同时测 | 6 / 10 / 11 / 16 / **18 / 35** 【需核实上限】 | 机时省、组内缺失值几乎为 0、批内可比性极好 | 试剂贵、**ratio compression**、**plex 边界 = 硬批次** |
| **SILAC** | stable isotope labeling by amino acids in cell culture（细胞培养稳定同位素标记） | 在培养基里用重同位素氨基酸代谢标记 | 2–3 | 标记在最上游 ⇒ 定量最准 | **只能用于可培养细胞**，动物/临床样本基本不适用 |
| **DIA** | data-independent acquisition（数据非依赖采集） | 见 2.2，是采集策略但常被当作定量策略 | 1 | 缺失值少、重现性好、深度好 | 数据分析更依赖软件，早期需要谱图库 |

**【判断】给你的默认建议**：**LFQ + DIA 是 2026 年的默认组合**。TMT 只在两种情况下用 —— ① 样本数多且机时紧张；② 需要极高的组内定量精度（例如做时间序列的细微变化）。**SILAC 在服务型业务里基本用不上**（客户寄来的样本已经长好了）。

### 2.2 维度二：采集策略（DDA vs DIA）—— 这是最重要的一格

| | **DDA** | **DIA** |
| :--- | :---: | :---: |
| 英文全称 | data-dependent acquisition（数据依赖采集） | data-independent acquisition（数据非依赖采集） |
| 工作方式 | MS1 扫一遍，挑**信号最强的前 N 个**离子去碎裂 | 把质荷比范围切成固定窗口，**逐窗口全部碎裂** |
| 类比 | 像"挑最亮的星星拍特写" | 像"整片天空扫描成像" |
| 谱图性质 | 干净（一个前体一张谱） | **混合谱**（一个窗口里几十个肽段的碎片叠在一起） |
| 缺失值 | **多**（每次挑的 N 个不一样 ⇒ 运行间不一致） | **少**（窗口是固定的 ⇒ 高度可重现） |
| 分析难度 | 简单（直接比对数据库） | **难**（必须解卷积；早期需要预先建谱图库） |
| 2026 现状 | 仍是 TMT / 磷酸化富集 / de novo 的主力 | **无标记定量的默认选择** |

**DIA 的关键转折点**：早期 DIA 必须先跑一批 DDA 建立"谱图库（spectral library）"，成本翻倍。**现在 DIA-NN 等工具支持从 FASTA 直接用深度学习预测谱图库（library-free / in-silico predicted library）**，这一步消失了。【文献】这是 DIA 从小众变成默认的直接原因。

> **⚠ 给客户沟通的注意事项**：DIA 与 DDA 的原始数据**不能混着分析**。如果一个项目里既有历史 DDA 数据又有新的 DIA 数据，那是**两个批次两条流程**，只能在最终结果层面做定性对照，不能合并进同一个统计模型。这与你在 RNAseq 项目里关于跨批次合并的既有立场一致。

### 2.3 维度三：范围（发现型 vs 靶向型）

| | **发现型（discovery / shotgun）** | **靶向型（targeted）** |
| :--- | :---: | :---: |
| 问题形式 | "哪些蛋白变了？"（假设生成） | "**这 20 个**蛋白变了多少？"（假设检验） |
| 方法 | DDA 或 DIA 全谱 | **PRM**（parallel reaction monitoring，平行反应监测）/ **MRM–SRM**（multiple / selected reaction monitoring，多重反应监测） |
| 蛋白数 | 数千 | 数个到数百 |
| 定量精度 | 中 | **高**（可绝对定量，配合同位素标准肽） |
| 软件 | DIA-NN / FragPipe / MaxQuant | **Skyline**（事实标准，几乎无替代） |
| 类比 RNAseq | RNA-seq | RT-qPCR / 靶向 panel |

**【判断】** 靶向蛋白组学在服务业务里的位置，等同于 RT-qPCR 在转录组业务里的位置：**它是发现型结果的验证手段，通常是第二轮业务**。首轮几乎总是发现型。

### 2.4 仪器与原始文件格式（决定你的预处理脚本）

| 厂商 | 主流机型 | 原始格式 | Linux 下怎么读 |
| :--- | :---: | :---: | :---: |
| **Thermo Fisher** | Orbitrap Exploris / Eclipse / **Astral** | `.raw`（单文件） | `ThermoRawFileParser` 转 mzML；DIA-NN / FragPipe 可直接读 |
| **Bruker** | **timsTOF Pro / HT / SCP** | `.d`（**目录**，不是文件） | DIA-NN / FragPipe 原生支持；注意它是目录，`ls` 和归档脚本要相应处理 |
| **Sciex** | ZenoTOF / TripleTOF | `.wiff` + `.wiff.scan` | 需转换；生态支持相对弱 |
| **通用开放格式** | — | **mzML**（HUPO-PSI 标准） | 所有工具都读；体积比原始格式大 2–5 倍【量级估算】 |

> **⚠ 两个实务陷阱**：
> ① **Bruker 的 `.d` 是目录**。如果你沿用 RNAseq 的 `find ... -type f` 清点脚本，会得到荒谬的文件数。清点必须按目录计，且要检查目录内部完整性。
> ② **`.raw` / `.d` 单次运行体积在 0.5–5 GB**【量级估算】，DIA 长梯度更大。一个 40 样本的 DIA 项目，原始数据 100 GB 量级很常见。**磁盘规划要按这个量级做。**

### 2.5 特化子领域（知道它们存在即可）

| 子领域 | 要点 | 专用工具 |
| :--- | :---: | :---: |
| **磷酸化蛋白质组学（phosphoproteomics）** | 需磷酸肽富集（TiO₂ / IMAC）；核心难题是**位点定位（site localization）**；**必须做蛋白层归一化** | FragPipe（PTM-Shepherd）、`PhosR`、`MSstatsPTM` |
| **其他翻译后修饰（PTM，post-translational modification）** | 泛素化（K-GG）、乙酰化、糖基化 | 同上；糖基化另有 pGlyco / MSFragger-Glyco |
| **单细胞蛋白质组学（single-cell proteomics）** | 深度约 1,000–3,000 蛋白/细胞【量级估算，需核实】；载体通道（carrier channel）设计争议大 | Bioconductor **`scp`**、SCoPE2 协议、timsTOF SCP |
| **成像质谱（MS imaging）** | 空间分辨的蛋白/代谢物分布 | R **`Cardinal`** |
| **血浆 / 体液蛋白质组学** | **白蛋白等高丰度蛋白占绝大部分蛋白质量** ⇒ 不做去除只能看到几百个蛋白 | depletion 柱、纳米颗粒富集（Seer 等）、或改用亲和平台 |
| **亲和蛋白质组学（非质谱）** | **Olink**（PEA，proximity extension assay）、**SomaScan**（适配体） | **不是质谱**，是靶向 panel。数据分析完全不同（走 NPX 值 + limma） |

> **【判断】** Olink / SomaScan 值得单独知道，因为**客户经常把它们和质谱蛋白组学混为一谈**。它们通量高（数千蛋白）、缺失值少、适合大队列，但**测的是"抗体/适配体能结合的东西"而不是"实际存在的肽段"**，特异性争议持续存在，且**无法发现未预设的蛋白**。如果客户说"我要做 3000 个蛋白的血浆蛋白组，200 个样本"，他大概率想要的是 Olink 而不是质谱。

## §3 分析全流程七阶段（每一步对照 RNAseq）

这是全文的骨架。**先建立这张对照表，后面的工具名才有位置可挂。**

| 阶段 | 蛋白组学做什么 | RNAseq 的对应物 | 主力工具 |
| :--- | :---: | :---: | :---: |
| **0. 原始数据与转换** | `.raw` / `.d` → （可选）mzML | FASTQ 获取与校验 | ThermoRawFileParser |
| **1. 鉴定（identification）** | 谱图比对蛋白序列数据库，得到 PSM | **比对（alignment）** | MSFragger / Comet / Sage / DIA-NN |
| **2. 错误率控制（FDR control）** | target-decoy + 重打分，PSM/肽段/蛋白三层 FDR | MAPQ 过滤 + 变异 caller 的过滤 | Percolator / mokapot / MSBooster |
| **3. 定量（quantification）** | 提取峰面积 / 报告离子强度 | **计数（featureCounts / Salmon）** | IonQuant / MaxLFQ / directLFQ / TMT-Integrator |
| **4. 矩阵组装与 QC** | 肽段 → 蛋白 rollup；污染物剔除；PCA | 计数矩阵 + PCA + 样本聚类 | R：`QFeatures` |
| **5. 归一化与缺失值** | median / quantile / VSN；MNAR 建模或填补 | 文库大小归一化（这一步 RNAseq 简单得多） | R：`limma` / `msqrob2` / `MSstats` |
| **6. 差异丰度（differential abundance）** | 线性模型 + 经验贝叶斯 | **DESeq2 / edgeR / limma-voom** | R：`limma` / `MSstats(TMT)` / `msqrob2` / `DEqMS` |
| **7. 解读** | 富集、通路、复合物、网络 | clusterProfiler / GSEA | R：`clusterProfiler` / `fgsea` / `STRINGdb` |

**关键观察**：**阶段 0–3 是蛋白组学特有的、由独立二进制程序完成的；阶段 4–7 与你现有的 RNAseq 下游工作流高度同构。**

**⇒ 这直接决定了语言选型**（§5）：你需要新学的"蛋白组学专门知识"集中在 0–3，而那一段**根本不涉及 R/Python 之争**；到了 4–7，你现有的 R 技能可以直接迁移 80%。

### 3.1 阶段 1–2 的核心概念：target-decoy 与三层 FDR

这是蛋白组学**唯一一个你在 RNAseq 里没有对应经验的统计概念**，值得单独说清。

**问题**：谱图比对数据库时，软件总能给每张谱图找到一个"最像"的肽段 —— 哪怕这张谱图其实是噪声。怎么知道哪些匹配是真的？

**解法：诱饵数据库（decoy database）**。把真实蛋白序列（target）反转或打乱，生成同样大小的假序列库，两者合并一起搜。**任何匹配到 decoy 的结果必然是假的**。于是：

```
FDR ≈ (匹配到 decoy 的数量) / (匹配到 target 的数量)
```

调整打分阈值使 FDR = 1%，就得到了受控的结果集。**这是蛋白组学"1% FDR"这句行话的来源。**

> **⚠ 三个必须理解的细节：**
> 1. **FDR 在三个层级各自控制：PSM 层 → 肽段层 → 蛋白层。** 三者不等价，**且蛋白层 FDR 会随样本数增加而被稀释**（多次实验累积，1% PSM-FDR 可能对应远高于 1% 的蛋白 FDR）。大型项目必须显式做**蛋白层 FDR**（picked-protein FDR 等方法）【文献】。
> 2. **PSM = peptide-spectrum match（肽段-谱图匹配）**，是最小的鉴定单位。一个蛋白由多条肽段支持，一条肽段由多张 PSM 支持。
> 3. **重打分（rescoring）能显著提升鉴定数**：用机器学习把多个特征（打分、质量误差、保留时间偏差、预测碎片强度相似度）组合成单一判别值。`Percolator` 是经典实现，`mokapot`（Python）是其现代重写，`MSBooster` + Prosit/DeepLC 预测值可再提升一档。**【判断】** 这是"免费"的深度提升（不用重测），性价比极高，值得纳入标准流程。

### 3.2 阶段 3 的核心概念：肽段 → 蛋白的"rollup"

搜索引擎给你的是**肽段级**定量。但客户要的是**蛋白级**。怎么合并？

| 方法 | 做法 | 特点 |
| :--- | :---: | :---: |
| **求和 / 平均** | 直接加总肽段强度 | 简单但对缺失值极敏感（少一条肽段就整体降低） |
| **Top-N（如 Top3）** | 只用信号最强的 N 条肽段 | 老方法，稳健但浪费信息 |
| **MaxLFQ** | 基于样本间**成对肽段比值**的中位数做最大似然估计 | **MaxQuant / DIA-NN 的默认**，对缺失值稳健，事实标准【文献】 |
| **directLFQ** | MaxLFQ 思路的线性时间实现 | 大规模项目（数千样本）时用，Python【需核实】 |
| **中位数抛光（median polish）** | 稳健的行列效应分解 | TMT 常用 |
| **不 rollup** | 直接在肽段层建统计模型，蛋白效应作为参数估计 | **`msqrob2` / `MSstats` 的路线**，统计上最优 |

> **【判断】这是我认为最值得投入理解的一个点。** rollup 会**丢失方差信息** —— 一个由 30 条肽段支持的蛋白和一个由 1 条肽段支持的蛋白，rollup 后长得一模一样，但可信度差一个数量级。两条补救路线：
> - **`DEqMS`**：把肽段/PSM 计数作为方差先验喂给经验贝叶斯，让"证据少"的蛋白自动获得更保守的 p 值。**这是在已有 rollup 矩阵上最省事的正确做法。**
> - **`msqrob2` / `MSstats`**：干脆不 rollup，在肽段层建模。统计上更优，但要求你能拿到肽段级输出，且模型设定更复杂。

## §4 生态系统全景

这一节是"有哪些生态系统"的正面回答。我按**层**来组织，而不是按语言 —— 因为**层比语言更能决定你的选择**。

### 4.1 第一层：搜索引擎与定量引擎（语言无关的独立程序）

**这一层是蛋白组学的"比对器"，相当于 RNAseq 里的 STAR / Salmon。它们几乎都是 C++ / C# / Rust / Java 写的独立二进制，你只是调用者。**

| 工具 | 出处 | 语言/形态 | DDA | DIA | 许可证【需核实】 | 定位 |
| :--- | :---: | :---: | :---: | :---: | :---: | :---: |
| **DIA-NN** | Demichev / Ralser 等 | C++ 二进制 + GUI | 部分 | **★核心** | 学术免费 | **DIA 的事实标准**；速度快、深度好、支持预测谱图库 |
| **FragPipe**（含 **MSFragger**） | Nesvizhskii 实验室（U. Michigan） | Java GUI + 多组件 | **★核心** | ★（内嵌 DIA-NN） | 学术免费，商业需授权 | **功能最全的一站式平台**；开放式搜索、PTM、TMT 全覆盖 |
| **MaxQuant** | Mann 实验室 | C# / .NET | **★核心** | ✓ | 免费 | **历史最悠久、文献最多**；Linux 支持较别扭；配套 GUI 是 Perseus |
| **Sage** | Michael Lazear | **Rust**，开源 MIT | ★ | 部分 | 完全开源 | **极快、极简、无依赖**；适合嵌入自建管线 |
| **AlphaPept / AlphaDIA** | Mann 实验室 | **Python**，开源 | ✓ | ★ | Apache | **纯 Python 的现代实现**；可读性好、易改；生态含 alphabase / alphapeptdeep |
| **OpenMS** | 学术联盟（欧洲） | C++ + **pyOpenMS** | ✓ | ✓ | 开源 BSD | **不是搜索引擎，是工具箱/框架**；nf-core/quantms 的底座 |

> - **DIA-NN + FragPipe 两个就够覆盖 95% 的项目**，且都是学术免费、Linux 可跑、可脚本化。
> - **MaxQuant 要会读它的输出**（`proteinGroups.txt` / `evidence.txt`），因为大量历史数据和客户已有结果是它产的 —— 但**不必把它作为新项目的首选**（Linux 下运行体验较差）。
> - **Sage 值得关注**：如果将来要把蛋白组学做成 Nextflow 管线并追求速度，它是最容易嵌入的。
> - **商业软件不必买**：DIA-NN 与 Spectronaut 的差距，在多数常规项目上不足以支撑授权成本。【判断】

### 4.2 第二层：管线编排（★ 这一层与你现有能力最贴合）

| 方案 | 说明 | 与你的关系 |
| :--- | :---: | :---: |
| **nf-core/quantms** | **Nextflow 管线**，底座是 OpenMS；支持 DDA-LFQ、DDA-ISO（TMT）、DIA（DIA-NN）三条路线；用 **SDRF** 作样本表；输出 mzTab + MSstats 输入格式【需核实版本与三条路线的成熟度】 | **★ 这是你最应该先试的东西。** 与 sarek / rnaseq / mag / taxprofiler 同一套心智模型：`-profile conda`、`-resume`、`work/` 目录管理、资源配置文件 —— 你已有的全部 Nextflow 经验直接复用 |
| **FragPipe workflow 文件** | FragPipe 的分析配置可保存为 `.workflow` 文件并用命令行 headless 运行 | 适合把"某类项目的标准参数"固化下来，等价于你的 numbered step scripts |
| **SDRF-Proteomics** | HUPO-PSI 的标准化样本元数据格式（sample and data relationship format） | **相当于蛋白组学版的样本表标准**。与你的 `0_sample_table.csv` 作为 SSOT（single source of truth，单一事实来源）的做法理念一致，可以直接从 CSV 生成 |

> **【判断】** nf-core/quantms 是你进入这个领域**成本最低的切入点** —— 它把 §3 的阶段 0–3 全部包起来，你只需要提供 FASTA、原始文件和 SDRF 样本表，拿到可直接进 R 的定量矩阵。**但要有心理准备**：它的成熟度和用户基数**不如 sarek / rnaseq**，遇到问题时社区支持较薄，参数调优的空间也更大。**首次上手务必先跑官方 test profile。**

### 4.3 第三层：下游统计 —— **R 生态**（这是 R 压倒性领先的地方）

#### 4.3.1 数据结构层（地基）

| 包 | 作用 | 对应你已知的 |
| :--- | :---: | :---: |
| **`QFeatures`** | **蛋白组学的标准容器**。把 PSM → 肽段 → 蛋白的多层关系存在一个对象里，并**记录每一步聚合的血缘（provenance）** | `SummarizedExperiment` 的多层扩展；类比 `SingleCellExperiment` 在 scRNA 的地位 |
| **`SummarizedExperiment`** | Bioconductor 通用矩阵容器 | 你在 DESeq2 里已经天天用 |
| **`MSnbase`** | 上一代容器（`MSnSet`） | **已被 QFeatures 取代**；老教程里大量出现，新项目不要用【判断】 |
| **`Spectra`** / `mzR` | 谱图级数据的读取与操作 | 相当于 `Rsamtools`，多数下游分析用不到 |

> **【判断】** **`QFeatures` 是理解 R 蛋白组学生态的钥匙。** 它扮演的角色，与 `SummarizedExperiment` 在 RNAseq、`SingleCellExperiment` 在 scRNA 里完全一样：**一个共享的数据契约，让不同作者的包能互相衔接。** Python 侧缺的正是这个东西 —— 各包各有各的 DataFrame 约定。

#### 4.3.2 差异丰度统计（核心竞争力）

| 包 | 统计模型 | 何时用 | 缺失值处理 |
| :--- | :---: | :---: | :---: |
| **`limma`** | 线性模型 + **经验贝叶斯方差收缩** | **通用首选**。任何已经 rollup 成蛋白矩阵的数据 | 需先填补或过滤 |
| **`DEqMS`** | limma 的扩展，**用肽段/PSM 计数做方差先验** | **在 limma 基础上零成本升级**，只要你有每个蛋白的肽段数 | 同 limma |
| **`MSstats`** | **线性混合模型**，直接在 feature（肽段/碎片）层建模 | 设计复杂（配对、时间序列、多因素）；DIA 项目 | 内置处理 |
| **`MSstatsTMT`** | MSstats 的 TMT 专版，**显式建模 plex 批次与参考通道** | **所有 TMT 项目的默认**，不要用别的 | 内置 |
| **`MSstatsPTM`** | PTM 位点分析，**自动做蛋白层归一化** | 磷酸化项目 | 内置 |
| **`msqrob2`** | **稳健岭回归**，肽段层建模，**不填补缺失值** | 缺失值多的 LFQ 项目；统计上最讲究的路线 | **显式建模，不填补** |
| **`proDA`** | **概率化 dropout 模型**，把 MNAR 当作左删失显式建模 | 缺失值极多、且缺失本身有信息时 | **显式建模** |
| **`prolfqua`** | 综合工作流包，覆盖归一化到检验 | 想要一个"全包"方案时 | 多种可选 |
| **`NormalyzerDE`** | **系统比较多种归一化方法**并给出评估图 | **项目早期用它选归一化策略**，而不是拍脑袋 | — |
| **`DEP`** | 老牌一站式（含 Shiny） | 教程多、上手快；**维护活跃度不如上面几个**【需核实】 | 内置填补 |

> **【判断】三条推荐路线，按项目复杂度递进：**
> 1. **入门 / 简单两组比较**：`limma` + `DEqMS`。你已经会 limma，学习成本近乎为零。
> 2. **DIA 或复杂设计**：`MSstats`。它是 DIA 领域引用最广的统计框架，客户/审稿人接受度最高。
> 3. **缺失值特别多、想做到统计上最干净**：`msqrob2`（基于 QFeatures，与 Bioconductor 生态咬合最紧）。
>
> **不要在第一个项目就上 msqrob2。** 先用 limma 把整条流程跑通，再回头升级统计层。

#### 4.3.3 专项与解读

| 包 | 领域 |
| :--- | :---: |
| **`PhosR`** | 磷酸化：位点级归一化、激酶活性推断、信号网络重建 |
| **`scp`** | **单细胞蛋白质组学的 Bioconductor 参考实现**（基于 QFeatures） |
| **`Cardinal`** | 成像质谱（MS imaging）的空间统计与分割 |
| **`artMS`** | 亲和纯化质谱（AP-MS）与蛋白互作 |
| **`clusterProfiler`** / **`fgsea`** / **`ReactomePA`** | **富集分析 —— 你已经在用，直接复用**（注意背景集，见 §7.6） |
| **`STRINGdb`** / `rbioapi` | 蛋白互作网络、STRING 富集 |

### 4.4 第三层：下游统计 —— **Python 生态**（诚实评估：不完整）

| 包 | 作用 | 成熟度评价 |
| :--- | :---: | :---: |
| **`pyteomics`** | **解析 mzML / mzIdentML / mzTab / FASTA**，肽段质量计算、色谱工具 | **★ 优秀且不可替代**。R 侧没有同等易用的东西 |
| **`pyOpenMS`** | OpenMS C++ 库的 Python 绑定，完整的信号处理算法 | ★ 强大但 API 偏底层，学习曲线陡 |
| **`alphastats`（AlphaPeptStats）** | **Python 侧最接近"完整下游分析"的包**：读取 MaxQuant/DIA-NN/FragPipe 输出、归一化、填补、差异分析、可视化 | ✓ 可用。**但统计层是 t 检验 / ANOVA / sklearn 那一档，没有经验贝叶斯方差收缩**【判断：这是它与 limma 的本质差距，不是版本问题】 |
| **`mokapot`** | Percolator 的 Python 重写，PSM 重打分 | ★ 现代、可脚本化，**优于 R 的任何选择** |
| **`pyprophet`** | DIA / OpenSWATH 结果的统计验证 | ✓ 该场景下的标准工具 |
| **`directlfq`** | 线性时间的 LFQ 归一化与蛋白定量 | ✓ 大规模项目有用 |
| **`alphabase` / `alphapeptdeep` / `alphamap` / `alphaviz`** | Mann 实验室的 Python 全家桶：数据结构、深度学习预测、序列映射、可视化 | ✓ 现代、活跃，**是 Python 侧最有前途的方向** |
| **`spectrum_utils`** | 谱图处理与**发表级谱图注释图** | ★ 画谱图这件事上明确优于 R |
| **`scanpy` / `anndata`** | 单细胞蛋白质组学（如果你选择走 Python 路线） | ✓ 可用，但 `scp` 更贴合该领域惯例 |
| **`msstitch`** | 搜索引擎输出的整理与合并 | ✓ 小众但实用 |

> **【判断】Python 侧的真实定位**：**它在"靠近仪器"的那一端很强（解析、重打分、深度学习），在"靠近生物学结论"的那一端很弱（统计推断）。**
>
> **这个分工不是偶然**：靠近仪器的部分需要高性能循环与深度学习框架 → Python/C++ 的主场；靠近结论的部分需要成熟的统计模型与经验贝叶斯 → R/Bioconductor 二十年积累的主场。**⇒ 不要试图用一种语言干完全部。**

### 4.5 图形界面 / 无代码工具（值得知道，因为客户可能在用）

| 工具 | 说明 | 【判断】 |
| :--- | :---: | :---: |
| **Perseus** | MaxQuant 的官方配套 GUI（Windows），Mann 实验室出品 | 教程海量、生物学家爱用。**但不可脚本化、不可复现** ⇒ 不适合服务型交付 |
| **FragPipe-Analyst** / **LFQ-Analyst** | FragPipe 输出的网页版下游分析 | 快速看结果有用；正式交付仍应走 R 脚本 |
| **MSstatsShiny** | MSstats 的图形界面 | 学习 MSstats 参数含义时有用 |
| **Amica / ProVision** | 网页版差异分析与可视化 | 同上 |

> **⚠ 与你的既有原则的冲突点**：这些 GUI 工具**都不满足"结果可复现、参数可追溯"的要求**。可以用它们探索和交叉验证，**但客户交付的每一个数字必须来自可重跑的脚本**。这与你在 RNAseq 上的既有立场一致，不需要为蛋白组学破例。

### 4.6 深度学习层（2023 年以来变化最大的部分）

| 用途 | 代表工具 | 语言 | 说明 |
| :--- | :---: | :---: | :---: |
| **碎片谱图预测** | **Prosit**、MS2PIP、**AlphaPeptDeep** | Python | 从肽段序列预测 MS2 谱图 ⇒ **让 library-free DIA 成为可能** |
| **保留时间预测** | **DeepLC**、Prosit | Python | 增加一个正交特征用于重打分 |
| **重打分（rescoring）** | **MSBooster**（FragPipe 内置）、**Oktoberfest**（Prosit 流程） | Java / Python | **用预测谱图与实测谱图的相似度作为特征** ⇒ 鉴定数显著提升 |
| **离子淌度预测** | AlphaPeptDeep 等 | Python | timsTOF 数据的额外维度 |
| **De novo 测序** | **Casanovo**、InstaNovo、PEAKS | Python / 商业 | 不依赖数据库直接读序列；抗体测序、宏蛋白质组、新肽段发现 |

> **【判断】** **这一层完全是 Python 的天下，R 没有参与。** 但对你来说好消息是：**这些能力大多已经被封装进 FragPipe / DIA-NN 内部**，你不需要自己搭深度学习流程就能享受到收益。**只有做 de novo 或非常规修饰时才需要直接接触它们。**

### 4.7 数据库与知识资源

| 资源 | 内容 | 用途 |
| :--- | :---: | :---: |
| **UniProt** | **蛋白序列数据库**（搜索用的 FASTA 从这里下） | **必需**。注意选 Swiss-Prot（人工审编，约 2 万人类条目）还是 TrEMBL（自动，巨大） |
| **ProteomeXchange** | 公共数据的总门户 | 找练手数据 / 找对照数据集 |
| **PRIDE**（EBI） | 最大的蛋白组学数据仓库，PXD 编号 | **数据提交的默认目的地**（等价于测序的 GEO/SRA） |
| **MassIVE**（UCSD） | 另一大仓库 + MassIVE-KB 谱图库 | 备选提交地；谱图库资源 |
| **PeptideAtlas** | 经过统一再处理的肽段证据库 | 判断"某肽段是否可被观测到" |
| **Human Protein Atlas** | 蛋白表达与亚细胞定位（免疫组化 + 质谱） | 结果解读时查组织特异性 |
| **CPTAC** | 癌症临床蛋白组学联盟的配对多组学数据 | **多组学整合的最佳公共参照** |
| **PhosphoSitePlus** | 已知 PTM 位点与功能注释 | **磷酸化项目必查** |
| **CORUM** | 已知蛋白复合物 | 复合物水平的富集分析 |
| **STRING** / **Reactome** / **GO** | 互作网络 / 通路 / 功能注释 | 与 RNAseq 完全相同 |

> **⚠ FASTA 选择是一个静默影响结论的决定**：
> - **Swiss-Prot（canonical）** vs **Swiss-Prot + isoform** vs **+ TrEMBL**：库越大，搜索越慢，**且 FDR 控制下的鉴定数可能反而下降**（搜索空间变大 ⇒ 随机匹配增加）。
> - **必须加污染物库（contaminants）**：角蛋白（keratin，来自皮肤和头发）、胰蛋白酶自切肽、BSA。不加的话这些会被错误归属到真实蛋白上。cRAP 是通用污染物库。
> - **【判断】默认选择：Swiss-Prot canonical + 污染物库**。除非有特定需求（找新蛋白、非模式生物），不加 TrEMBL。
> - **在报告 Methods 里必须写明：数据库名称、版本/下载日期、条目数、是否含 isoform、污染物库来源。** 这与你在 RNAseq 报告里写参考基因组版本是同一性质的义务。

## §5 R vs Python：逐层正面比较

### 5.1 为什么这个问题的答案是"分层"而不是"二选一"

**问错问题会得到错答案。** "蛋白组学该用 R 还是 Python"这个问法暗含一个假设：整条流程是用一种语言写的。**但蛋白组学不是这样** —— 阶段 0–3 由独立二进制完成（§3），你写的代码只覆盖阶段 4–7 加上一些粘合。

所以真实的问题是三个：

1. **搜索层我调用什么？** → 答案与语言无关（DIA-NN / FragPipe，都是命令行或 GUI）。
2. **粘合与预处理用什么？** → **Python 略优**（pyteomics 解析能力强），但 R 也够用；**如果走 nf-core/quantms，这层大部分由 Nextflow 承担**。
3. **统计与出图用什么？** → **R，没有悬念。**

### 5.2 逐层详细对比

#### 层 A：原始文件解析与格式转换

| | R | Python |
| :--- | :---: | :---: |
| 主力 | `mzR` / `Spectra` | **`pyteomics`** / `pyOpenMS` |
| 评价 | 能用，但 API 老旧、文档少、性能一般 | **明显更好**：pyteomics 的 API 直观，覆盖 mzML/mzIdentML/mzTab/pepXML/FASTA |
| **结论** | — | **Python 胜，差距中等** |

**但注意**：**多数项目根本不需要碰这一层** —— 搜索引擎直接读原始格式并输出 TSV。只有做质控深挖、自定义算法或谱图可视化时才需要。

#### 层 B：重打分与 FDR 精细控制

| | R | Python |
| :--- | :---: | :---: |
| 主力 | 几乎没有 | **`mokapot`** / `pyprophet` |
| **结论** | — | **Python 胜，差距大**（R 侧基本空白） |

#### 层 C：定量矩阵组装、QC、归一化

| | R | Python |
| :--- | :---: | :---: |
| 主力 | **`QFeatures`** + `limma::normalizeBetweenArrays` + `NormalyzerDE` | `alphastats` / pandas 手写 |
| 优势 | **统一数据契约**；多层血缘可追溯；`NormalyzerDE` 能系统比较归一化方案 | pandas 灵活；`directlfq` 快 |
| **结论** | **R 略胜** | 差距小；如果你 pandas 很熟，Python 这一层不吃亏 |

#### 层 D：差异丰度统计 —— **决定性的一层**

| | R | Python |
| :--- | :---: | :---: |
| 可用方法 | limma（经验贝叶斯）、MSstats（线性混合模型）、msqrob2（稳健回归 + 缺失建模）、proDA（dropout 概率模型）、DEqMS（计数加权方差先验） | t 检验、ANOVA、`statsmodels` 的线性模型、sklearn |
| 小样本表现 | **经验贝叶斯跨蛋白借力估计方差 ⇒ n=3 时仍稳健** | **逐蛋白独立估计方差 ⇒ n=3 时方差估计极不稳定，假阳性率高** |
| 缺失值 | msqrob2 / proDA / MSstats 显式建模 | 只能先填补 |
| 复杂设计 | 配对、批次、时间序列、混合效应全支持 | statsmodels 可写，但没有蛋白组学专用的方差收缩 |
| 审稿人/客户接受度 | **MSstats、limma 是文献里的默认引用** | 需要额外解释 |
| **结论** | **R 压倒性胜出** | **这一层不存在权衡** |

> **【判断】这是全文最重要的一段。** 我见过的把蛋白组学做砸的方式，最常见的就是"用 pandas 读矩阵 → scipy 做 t 检验 → 挑 p<0.05"。这个流程**在 n=3 时会产生大量假阳性**，而且**输出看起来完全正常**（有火山图、有 p 值、有基因列表），错误无法从结果本身看出来。
>
> 经验贝叶斯方差收缩（limma 的核心）解决的正是这个问题：**它假设"大多数蛋白的方差来自同一个分布"，于是可以用全部蛋白的信息来稳定每个蛋白的方差估计。** 这在 n=3 时的收益是决定性的。**Python 里没有这个东西。**

#### 层 E：富集分析与通路解读

| | R | Python |
| :--- | :---: | :---: |
| 主力 | **`clusterProfiler`** / `fgsea` / `ReactomePA` / `STRINGdb` | `gseapy` / `gprofiler-official` |
| **结论** | **R 胜，差距大**；且**你已经在用** | gseapy 可用但注释资源整合弱 |

#### 层 F：出版级图件

| | R | Python |
| :--- | :---: | :---: |
| 主力 | **`ggplot2`** + `ComplexHeatmap` + `EnhancedVolcano` | matplotlib / seaborn |
| **对你的额外权重** | **你已有一套 house style 与配色优先级规范** ⇒ 蛋白组学图件可与 RNAseq 报告完全统一 | 需重建一套 |
| **结论** | **R 胜**（对你而言差距更大） | 例外：**谱图注释图** `spectrum_utils` 更好 |

#### 层 G：单细胞蛋白质组学

| | R | Python |
| :--- | :---: | :---: |
| 主力 | **`scp`**（Bioconductor，该领域参考实现） | `scanpy` + `anndata`（需自行适配） |
| **结论** | **R 略胜**（领域惯例在 R） | 但如果规模极大或要与你现有 scRNA Python 管线整合，Python 也合理 |

### 5.3 一个反直觉的观察

**"蛋白组学是 R 的天下"和"最先进的蛋白组学工具是 Python 写的"这两句话同时为真，不矛盾。**

- **Python 赢在"新"**：深度学习、现代重写（AlphaPept、mokapot、Casanovo）都是 Python，因为这些方向需要的是 PyTorch 和快速迭代。
- **R 赢在"深"**：差异分析的统计方法学积累了二十年（limma 从 2004 年的芯片时代就在打磨小样本方差问题），而这些方法**至今没有被 Python 社区重新实现**，因为重新实现它们的动机很弱 —— 用的人直接调 R 就行了。

**⇒ 结论不是"选新的"或"选深的"，而是"各取所长"。**

### 5.4 与你的 scRNA 选型对照（这个对比很有帮助）

| | scRNA-seq | **蛋白质组学** |
| :--- | :---: | :---: |
| 主语言 | **Python**（Scanpy） | **R**（Bioconductor） |
| 辅助语言的位置 | R 补三块：pseudobulk 差异分析、空间统计、绘图 | Python 补三块：文件解析、重打分、深度学习 |
| 原因 | 单细胞的瓶颈是**规模与算法迭代速度** | 蛋白组学的瓶颈是**小样本统计推断的严谨性** |
| 桥接方式 | 走文件（不用 rpy2） | **同样走文件**（搜索引擎输出 TSV → R 读入） |

> **【判断】** "**走文件不走进程内互调**"这条原则在两个领域都成立，而且蛋白组学更容易做到 —— **因为搜索引擎本来就输出 TSV 文件**，天然就是文件边界。这意味着蛋白组学的跨语言协作**比 scRNA 更简单**，你不需要 reticulate 或 rpy2。

## §6 我的建议

### 6.1 一句话结论

> **R 作为主语言。Python 保持在"能读能改"的水平即可，用于解析原始文件与将来的深度学习需求。搜索引擎层学 DIA-NN 与 FragPipe 两个工具，管线层用 nf-core/quantms。**

### 6.2 理由（为什么对**你**尤其如此）

1. **你的 R 资产可以直接复用 70–80%**：limma 你会、clusterProfiler 你会、ggplot2 house style 你有、`DE_R45` 环境现成。蛋白组学下游真正的新东西只有 `QFeatures` 一个容器 + `MSstats` 一个统计包。
2. **你的交付形态是客户报告** —— 需要方法可辩护、引用可查。MSstats / limma 在审稿层面的接受度是 Python 方案给不了的。
3. **你的项目普遍是小样本（n=3）** —— 这正是经验贝叶斯方差收缩收益最大、Python 方案劣势最大的区间。
4. **你已经很熟 Nextflow / nf-core** —— quantms 让你的管线经验直接迁移，而不是从零学一个新的编排系统。
5. **图件统一性**：如果同一个客户既做 RNAseq 又做蛋白组学（这是常见的追加业务），**两份报告的图应该长得像出自同一个人之手**。用 R 才做得到。

### 6.3 三套具体技术栈

#### 栈 A：DIA 项目（推荐默认）

```
原始 .raw / .d
  → DIA-NN（library-free，FASTA 预测谱图库）
  → report.tsv / report.pg_matrix.tsv
  → R: QFeatures 读入 → 过滤污染物/decoy → log2 → median 归一化
  → R: limma（+DEqMS）  或  MSstats
  → R: clusterProfiler / fgsea + STRINGdb
  → R: ggplot2 出图（复用 house style）
```

#### 栈 B：TMT 项目

```
原始 .raw
  → FragPipe（MSFragger + TMT-Integrator，工作流选 TMT）
  → PSM.tsv / 各层级报告
  → R: MSstatsTMT（★ 必须用它，因为要建模 plex 批次与参考通道）
  → 后续同栈 A
```

#### 栈 C：LFQ-DDA 项目（或客户已有 MaxQuant 结果）

```
proteinGroups.txt / evidence.txt（客户已有）  或  FragPipe 新跑
  → R: QFeatures::readQFeatures()
  → 过滤：Reverse / Potential contaminant / Only identified by site 三列必须剔除
  → R: limma + DEqMS，或 msqrob2（缺失值多时）
  → 后续同栈 A
```

### 6.4 环境规划建议

**【判断】建议新建两个环境，不要污染 `regular_bioinfo`：**

| 环境名（建议） | 内容 | 理由 |
| :--- | :---: | :---: |
| **`proteomics`** | DIA-NN、ThermoRawFileParser、pyteomics、mokapot、（可选）FragPipe 依赖 | 搜索层依赖重且版本敏感 |
| **`proteomics_r`** 或复用 **`DE_R45`** | Bioconductor：QFeatures、limma、MSstats、MSstatsTMT、DEqMS、msqrob2、clusterProfiler | **【判断】先试试能否直接装进 `DE_R45`** —— 你已经在那里做 RNAseq 差异分析，共用能省一套依赖。若 Bioconductor 版本冲突再拆 |

> **⚠ 依赖安装需要你明确批准**（按既有规则我不会自行 install）。上面只是规划建议。

### 6.5 4 周上手路径（具体到可执行）

| 周 | 目标 | 具体做什么 | 完成标志 |
| :--- | :---: | :---: | :---: |
| **第 1 周** | **建立数据直觉** | 从 PRIDE 下载一个**公开的两组比较 DIA 数据集**（选样本数少、有明确阳性对照的，例如物种混合 benchmark 数据集）。**不跑搜索**，直接下载作者提供的定量矩阵，在 R 里读进来 | 能画出：缺失值热图、样本间强度分布箱线图、PCA。**能说出这个矩阵有多少 % 缺失值** |
| **第 2 周** | **打通统计层** | 对上述矩阵跑完整下游：过滤 → log2 → 归一化 → limma → 火山图 → 富集。**同时用 t 检验跑一遍做对照** | 能量化说出 limma 与 t 检验结果差多少，**并解释为什么** |
| **第 3 周** | **打通搜索层** | 拿同一数据集的原始文件（`.raw` 或 `.d`），**用 DIA-NN 自己搜一遍**，和作者的矩阵对比 | 能复现出**同一量级**的蛋白鉴定数。差异能归因（FASTA 版本、参数、FDR 设置） |
| **第 4 周** | **管线化** | 跑通 **nf-core/quantms 的 test profile**，然后用它跑第 3 周那个数据集 | 有一份可 `-resume` 的 Nextflow 运行 + 一份 SDRF 样本表 |

**第 1 周的关键选择：数据集**。**【判断】** 建议选**物种混合 benchmark（spike-in benchmark）**类型的数据集 —— 例如把已知比例的酵母蛋白掺进恒定的人源背景。**这类数据集有真值**：酵母蛋白应该全部显著变化且倍数已知，人源蛋白应该全部不变。

**⇒ 你可以直接测量自己流程的假阳性率和假阴性率**，而不是只能看"结果看起来合不合理"。这与你在 splicing 项目里用 ENCODE 真值做外部召回率检验、以及"逐级过滤出 N 个候选必须交换样本角色反向跑一遍"的做法，是同一个方法论。**这一步不要跳过** —— 它是你唯一一次能在没有客户压力的情况下校准这条流程的机会。

### 6.6 明确不建议做的事

| 不要做 | 为什么 |
| :--- | :---: |
| **用 DESeq2 / edgeR 分析蛋白强度** | 分布假设不成立，见 §1.4。**这是最常见的致命错误** |
| **用 pandas + scipy.ttest 做差异分析** | n=3 时假阳性率高，且错误不可见，见 §5.2 层 D |
| **第一个项目就上 msqrob2 / proDA** | 先用 limma 把全流程跑通；统计层是最容易后续升级的部分 |
| **把 Perseus 的操作作为交付流程** | 不可复现、不可追溯 |
| **买 Spectronaut / Proteome Discoverer** | DIA-NN + FragPipe 覆盖 95% 需求且免费【判断】 |
| **承诺 isoform 级或结构域级结论** | bottom-up 数据原理上给不了，见 §1.2 |
| **用 RNAseq 结果"验证"蛋白组结果** | 基线相关性只有 0.4–0.6，见 §1.5 |
| **跳过 benchmark 数据集直接上客户项目** | 你将没有任何办法知道自己的流程是否正确 |

## §7 统计层的关键细节（最容易做错的地方）

这一节展开 §6 里一笔带过的技术点。**如果你只深入学一节，学这一节** —— 因为搜索引擎的参数错了通常会报错，而统计层的错误是静默的。

### 7.1 过滤：三类必须剔除的行

在任何计算之前，从矩阵里删掉：

| 类别 | MaxQuant 列名 | 说明 |
| :--- | :---: | :---: |
| **诱饵（decoy）** | `Reverse` == `+` | 反向序列，本来就是假的 |
| **污染物（contaminant）** | `Potential contaminant` == `+` | 角蛋白、胰蛋白酶、BSA |
| **仅靠修饰位点鉴定** | `Only identified by site` == `+` | 证据不足以支持蛋白存在 |

**⇒ 忘记这一步的后果**：角蛋白（人的皮肤/头发污染）常常是丰度最高的几个"蛋白"之一，会主导 PCA 和归一化。**【判断】** 这一步应该写成流程里的硬断言（assert 剔除后 decoy 数 == 0），而不是靠记得。

**另外**：多数流程还会要求"至少在某一组的 N 个样本里被检出"（例如 3 个重复里至少 2 个）。**这个阈值直接决定了后续缺失值的多少，必须在 Methods 里写明。**

### 7.2 归一化

| 方法 | 适用 | 说明 |
| :--- | :---: | :---: |
| **中位数（median / median-centering）** | **通用默认** | 假设多数蛋白不变。简单稳健 |
| **分位数（quantile）** | 样本间分布形状差异大时 | 强力但假设更强（强制所有样本分布相同） |
| **VSN**（variance stabilizing normalization，方差稳定归一化） | 强度依赖的方差结构明显时 | 同时做变换和归一化 |
| **IRS**（internal reference scaling，内参缩放） | **多个 TMT plex 之间** | **多 plex TMT 必需**。用每个 plex 里的共同参考通道把不同 plex 拉到同一尺度 |
| **Loess / cyclic loess** | 强度依赖的偏倚 | limma 里可用 |

> **【判断】** 不要凭感觉选。**用 `NormalyzerDE` 在项目早期系统比较**，它会输出各方法的评估图（组内变异、PCA 分离度等）。选定后在 Methods 里写明选择依据。这比"我们用了中位数归一化"更可辩护。

### 7.3 缺失值：三条路线，选一条并说明

| 路线 | 做法 | 适用 | 风险 |
| :--- | :---: | :---: | :---: |
| **① 不填补，显式建模** | `msqrob2` / `proDA` / `MSstats` 把缺失作为模型的一部分 | **统计上最优** | 学习成本高；模型假设需要理解 |
| **② 区分机制填补** | 判断每个缺失是 MNAR 还是 MCAR：MNAR 用左删失填补（如 MinProb / QRILC，填在分布左尾），MCAR 用 kNN | 折中方案，`DEP` / `MSnbase` / `imputeLCMD` 支持 | 机制判断本身有主观性 |
| **③ 严格过滤后填补** | 先要求"每组至少 N/3 检出"，剩下的少量缺失用简单方法填 | **最简单、最常用** | 丢弃的蛋白里可能有真正的 on/off 信号 |

> **【判断】给你的建议**：**从路线 ③ 起步，但必须额外报告被过滤掉的蛋白里的"完全 on/off"候选**。
>
> 具体做法：过滤前先单独找出"在 A 组全部检出、B 组全部缺失（或反之）"的蛋白，**单列一张表交付**，注明"这些蛋白因在一组中完全未检出而无法进行统计检验，属于潜在的定性变化，需要靶向验证"。
>
> **理由**：这类蛋白在生物学上往往是最有意思的（完全的开关变化），但任何基于强度的统计模型都处理不好它们。**把它们当作"定性发现"单独交付，比塞进统计模型里给一个假的 p 值诚实得多**，也比默默丢弃负责。这与你"能证伪≠能证实"和"不写模糊结论"的既有立场一致。

### 7.4 统计模型的选择

**决策树：**

```
是 TMT 且有多个 plex？
  ├─ 是 → MSstatsTMT（必须，因为要处理 plex 批次）
  └─ 否 →
      设计是否复杂（配对/时间序列/多因素/嵌套）？
        ├─ 是 → MSstats（线性混合模型）
        └─ 否 →
            缺失值比例是否很高（>30%）？
              ├─ 是 → msqrob2 或 proDA
              └─ 否 → limma + DEqMS  ← 【推荐起点】
```

### 7.5 磷酸化的特殊要求（如果做）

**磷酸化项目有一个必做步骤，漏掉会直接得出错误结论：**

> **磷酸化位点强度必须除以对应蛋白的总量（蛋白层归一化）。**

**为什么**：如果蛋白 X 的总量增加了 2 倍，那么它的磷酸化位点强度自然也会增加约 2 倍 —— 但这**不代表磷酸化调控增强了**，只代表底物变多了。**不做归一化就会把"表达变化"读成"信号通路激活"。**

**⇒ 这要求磷酸化项目必须同时做一份"全蛋白组（global proteome）"作为分母。** 只做富集的磷酸化组，无法区分这两种情况。**这一点必须在项目设计阶段就跟客户说清楚，因为它意味着双倍的机时和成本。**

工具：`MSstatsPTM` 内置了这个逻辑；`PhosR` 也提供相应功能。

### 7.6 富集分析：背景集是最大的陷阱

**在 RNAseq 里，用全基因组（约 2 万基因）作为富集分析的背景集通常没问题**，因为 RNAseq 几乎能测到所有表达的基因。

**在蛋白组学里这是错的。** 一次实验可能只检出 6,000 个蛋白，而这 6,000 个**不是随机的 6,000 个** —— 它们系统性偏向高丰度蛋白：核糖体蛋白、代谢酶、细胞骨架。

> **⇒ 如果用全基因组做背景，你会得到一堆"核糖体""翻译""糖酵解"的假富集** —— 那反映的是**质谱能测到什么**，不是**你的处理做了什么**。

**正确做法**：**背景集 = 本次实验中被定量到的全部蛋白**（即进入统计检验的那个矩阵的全部行）。

在 `clusterProfiler` 里就是 `universe = ` 参数。**这个参数是可选的，忘了写不会报错** —— 这正是它危险的地方。【判断】应该写成流程里的强制参数。

### 7.7 样本量与检出力

**【判断】** 蛋白组学的 n=3 与 RNAseq 的 n=3 **不等价**，检出力更低，原因有三：

1. **技术变异更大**（进样量、色谱重现性、电离效率波动）；
2. **缺失值消耗自由度**（一个蛋白实际可用的样本数可能是 3+2 而不是 3+3）；
3. **动态范围压缩**（尤其 TMT 的 ratio compression，见 §8）使真实倍数变化被系统性低估。

**⇒ 报告写作含义**：当写"未检出显著差异蛋白"时，**必须同时说明检出力限制**（样本数、检出蛋白数、缺失值比例、能检出的最小倍数变化的量级）。否则客户会把"没测出来"读成"确实没变"。这与你在 splicing 综述里对阴性结论的处理原则完全一致。

## §8 陷阱清单

| # | 陷阱 | 后果 | 防御 |
| :--- | :---: | :---: | :---: |
| 1 | **用 DESeq2 / edgeR 分析强度数据** | p 值无意义，但输出看起来正常 | 记住：强度 ≠ 计数。用 limma 系 |
| 2 | **没剔除 decoy / 污染物 / only-by-site** | 角蛋白主导归一化与 PCA | 流程里写硬断言 |
| 3 | **把缺失值当 0** | log 后变 -Inf 或极端值 ⇒ 假阳性 | 见 §7.3 |
| 4 | **富集用全基因组做背景** | 一堆核糖体/翻译的假富集 | `universe =` 必填，见 §7.6 |
| 5 | **protein group 的多 ID 直接当基因符号** | `P12345;Q67890` 匹配不上任何注释，静默丢失 | 显式取 leading protein，并**记录丢失了多少行** |
| 6 | **TMT 的 ratio compression** | 真实倍数变化被系统性低估（可低估数倍） | 用 MS3/SPS-MS3 采集，或在解读时说明这是保守估计 |
| 7 | **多 plex TMT 未做 IRS 归一化** | plex 批次效应被当成生物学差异 | 用 MSstatsTMT；确保每 plex 有参考通道 |
| 8 | **混用不同定量列**（LFQ intensity / iBAQ / raw intensity / spectral count） | 数值不可比，量级差异巨大 | 在样本表/文档里锁定用哪一列，全程只用它 |
| 9 | **DDA 与 DIA 数据混合进同一统计模型** | 缺失模式完全不同，批次效应无法建模 | 视为两个批次，只做结果层定性对照 |
| 10 | **血浆样本未做高丰度蛋白去除** | 只能看到几百个蛋白，且被白蛋白主导 | 项目设计阶段就要定；或改用 Olink/SomaScan |
| 11 | **磷酸化未做蛋白层归一化** | 把表达变化读成信号激活 | 见 §7.5，必须配全蛋白组 |
| 12 | **Bruker `.d` 是目录，按文件清点** | 数据清点数字荒谬 | 清点脚本按目录计，并校验目录内部完整性 |
| 13 | **FASTA 版本未记录** | 结果不可复现 | Methods 必写：库名、版本/日期、条目数、是否含 isoform、污染物库 |
| 14 | **用 mRNA 数据"验证"蛋白结果** | 相关性只有 0.4–0.6，必然"不一致" | 见 §1.5，报告里先声明基线相关性 |
| 15 | **承诺 isoform / 结构域级结论** | 原理上做不到 | 见 §1.2，项目启动时说清 |
| 16 | **蛋白层 FDR 未单独控制** | 大项目里蛋白层实际 FDR 远高于 1% | 大规模项目显式做 picked-protein FDR |

## §9 与 RNAseq 的多组学整合

这是你最可能遇到的追加业务形态（客户已有 RNAseq，现在加做蛋白组）。

### 9.1 先说清基线

**必须在报告开头就写明：mRNA 与蛋白丰度的跨基因相关系数通常在 0.4–0.6。** 【文献】

**不写会怎样**：客户看到散点图上一片弥散的云，会认为"分析失败"或"样本搞错了"。**先给基线，再给数据，是唯一能避免这个误解的顺序。**

### 9.2 整合的四种层次（从易到难）

| 层次 | 做法 | 交付价值 |
| :--- | :---: | :---: |
| **① 重叠列表** | 两边的差异基因/蛋白取交集 | 最低。但客户最容易理解 |
| **② 四象限图** | x = mRNA log2FC，y = 蛋白 log2FC，标出四个象限 | **性价比最高**。同向变化 = 转录调控；只有蛋白变 = 翻译/降解调控 |
| **③ 通路层整合** | 两边各自做富集，比较通路层面的一致性 | 比基因层稳健得多（**基因层不一致，通路层常常一致**） |
| **④ 联合建模** | MOFA、mixOmics 等多组学因子分析 | 最高级但解释成本高；样本量小时不稳定【判断】 |

> **【判断】** 对常规服务项目，**做到 ② + ③ 就足够且最稳妥**。④ 需要较大样本量，且结果解释对客户来说门槛高。
>
> **② 的关键增值点**：**"mRNA 没变但蛋白变了"的那个象限，是纯蛋白组学才能提供的发现** —— 它直接指向翻译调控或蛋白稳定性变化。这是向客户说明"为什么值得加做蛋白组"的最有力论据。

### 9.3 ID 映射的实务问题

**蛋白组用 UniProt accession，RNAseq 用 Ensembl gene ID 或基因符号。** 映射不是一对一：

- 一个基因 → 多个 UniProt 条目（isoform、片段）；
- 一个 protein group → 多个基因；
- 约 5–15% 的条目会在映射中丢失【量级估算】。

**⇒ 必须报告映射损失率。** 「N 个蛋白中 M 个成功映射到基因符号（M/N = X%），未映射的主要为 ...」。这条与你"缺输入就写未做，不写成结论"的原则一致。

## §10 成本、算力与数据量（服务业务视角）

> **⚠ 以下全部是【量级估算】，用于可行性判断，不是报价。正式报价前必须按实际仪器机时与试剂价格核算。**

### 10.1 算力

| 步骤 | CPU | 内存 | 时间（40 样本 DIA） |
| :--- | :---: | :---: | :---: |
| 原始文件转换（如需） | 低 | 低 | 分钟级/样本 |
| **DIA-NN 搜索** | **高，可并行** | **高（预测库大时尤其）** | **数小时至一天** |
| FragPipe（DDA/TMT） | 高 | 中高 | 数小时 |
| R 下游分析 | 低 | 低 | 分钟级 |

**⇒ 你服务器的 28 核 / 56 线程上限完全够用**，瓶颈更可能是**内存**（DIA-NN 用大预测谱图库时）而不是 CPU。

**⇒ 长任务照旧必须放 tmux**，规则与你既有的 sarek / nf-core 运行方式完全一致。

### 10.2 存储

| 项目 | 量级 |
| :--- | :---: |
| 单次运行原始文件（`.raw` / `.d`） | 0.5–5 GB |
| 转成 mzML 后 | 原始的 2–5 倍 |
| 40 样本 DIA 项目原始数据 | **50–200 GB** |
| 搜索输出（TSV） | 数百 MB |
| 交付给客户的最终矩阵 | 数 MB |

**⇒ 与 WGS 项目同一量级，你现有的磁盘规划方式可直接套用。**

### 10.3 与 RNAseq 的成本对比结构

**【判断】** 蛋白组学的成本结构与测序**根本不同**：

| | RNAseq | 蛋白质组学 |
| :--- | :---: | :---: |
| 主要成本 | **试剂 + 测序芯片**（按数据量计） | **仪器机时**（按小时计）+ 样本前处理人工 |
| 边际成本 | 加深度 = 加钱，线性 | **加梯度时间 = 加机时**，且收益衰减快 |
| 多样本 | 可 pooling 上机，边际成本低 | **LFQ：机时 = 样本数，线性增长**；TMT 可摊薄 |
| 分析人工 | 成熟管线，人工低 | **前期高**（选型、参数、质控更依赖判断） |

**⇒ 报价逻辑要变**：RNAseq 按"样本数 × 数据量"，蛋白组学按"样本数 × 机时 + 是否标记"。**样本数多时 TMT 的成本优势才显现**（因为多样本共享一次上机）。
